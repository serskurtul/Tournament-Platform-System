# INC-001: Відмова завантаження банерів турнірів

| Поле | Значення |
|------|----------|
| Тип | **контрольована симуляція** (ЛР-12) на локальному стенді: API + PostgreSQL 15, `ASPNETCORE_ENVIRONMENT=Development` |
| Компонент | [сховище банерів](../architecture/legacy/storage-service.md) (`GoogleDriveStorageService` → Google Cloud Storage) |
| Сценарій | ключ сервісного акаунта відкликано: API налаштовано тимчасовим ключем, якого Google не знає (`scripts/ops/simulate_storage_outage.sh`) |
| Серйозність | **SEV-3**: недоступна неосновна функція (банер); реєстрація, каталог, сітка, результати працюють. Не SEV-2, бо турнір можна створити без банера |
| Годинник | UTC, 2026-11-22 |
| Стан | **FAIL**: workaround діє, причину не усунуто, RCA і CAPA в роботі |

**Час виявлення (TTD):** 66 с від початку впливу, лише вручну. **Час до workaround:** 81 с. В реальному житті без скарги TTD був би необмеженим: жоден сигнал моніторингу не змінився.

## Виконані дії

1. Перевірено `/health`, дашборд (через `/metrics`), логи API.
2. Локалізовано маршрут (тільки upload) і залежність (GCS / OAuth2).
3. Відтворено збій вручну, підтверджено `invalid_grant`.
4. Прийнято обхід: турніри без банера.

## Оцінка впливу

| Показник | Значення |
|----------|----------|
| Невдалих завантажень | **12 з 12 (100%)**, 1 організатор |
| Побічний ефект | турнір уже створено до завантаження (форма: create → upload в одному `try`), організатор бачить «Server error» з текстом `Failedo upload file to Google Cloud Storage: Error:"invalid_grant"…`; повторна відправка форми → **409** «Tournament title must be unique» (`evidence/incident-retry-409.txt`) |
| Інші сценарії | не зачеплено: 796/796 запитів каталогу успішні |
| Витік деталей | клієнту віддано внутрішнє повідомлення SDK і повне ім'я методу контролера |
