# Регламент підтримки документації

**Головне правило: зміна коду = зміна документації.** PR, який змінює поведінку (API, модель даних, розгортання), не зливається в `main` без оновлення зачеплених документів. Автоматична перевірка: джоба `doc-contract` у [`quality-metrics.yml`](../.github/workflows/quality-metrics.yml) запускає `scripts/quality/doc_contract_check.py`, яка падає, якщо маршрут API відсутній у [SDD](sdd.md) або порядок старту сервісів у `docker-compose.yml` не збігається з [ISD](isd.md). Решту рев'юер перевіряє за чекбоксом у шаблоні PR.

Цикли перегляду: експлуатаційна документація — не рідше ніж раз на **90 днів**, архітектурна — раз на **180 днів**. Перегляд = звірити з кодом, оновити дату в таблиці, закомітити.
