## Розглянуті аргументи

| Роль | Позиція | Аргументи |
|------|---------|-----------|
| Архітектор | за | Контракт і реалізація розійшлися: це дефект, не фіча. Новий ADR не потрібен: залежність `IUserRepository` у межах шару API → Infrastructure, як уже зроблено для `IParticipantRoster`. Вимога: контракт оновити в тому самому PR (SSOT, ЛР-11) |
| Лідер QA | за з умовами | Регресійний ризик низький, але заглушку ніхто не тестував. Вимога: тести на 200 / 401 / 404 і зелений контрактний тест після додавання операції в `openapi.yaml` |
| SRE | за з умовами | Міграцій немає, відкат — `helm rollback` ≤ 5 хв. Вимога: у релізі не має бути міграцій схеми (тоді `helm rollback` безпечний для даних); 15 хв спостереження за 5xx після релізу |
| Продуктовий власник | за | Відновлення сесії без повторного логіну — помітне покращення UX; термін — поточний спринт |

## Рішення

**Погоджено з умовами** (4 «за», 0 «проти»).

Умови виконання:

1. У тому самому PR оновити `docs/api/openapi.yaml` (minor 1.2.0), CHANGELOG і SDD §4.
2. Юніт-тести 200/401/404, `dotnet test` і контрактний тест зелені.
3. Реліз без міграцій схеми; план відкату з RFC — під рукою.
4. Після релізу 15 хв моніторингу 5xx.
