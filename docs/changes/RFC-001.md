## Опис і мета

`GET /api/v1/users/me` (`AuthController.Me`) повертає заглушку: щоразу новий випадковий `Id`, `player@example.com`, `Sample Player`, `Role = "Player"`, незалежно від токена. Це зафіксовано як технічний борг у ЛР-9 і в [SDD §4](../architecture/sdd.md). Мета: повертати профіль власника токена (`sub`), той самий, що й у відповіді `POST /auth/login`.

## Обґрунтування

- **Цінність:** клієнт (і майбутній SDK з `openapi.yaml`) зможе відновити профіль після перезавантаження сторінки за access-токеном, без повторного логіну.
- **Архітектура:** ендпоінт обіцяє в Swagger «профіль поточного користувача», а повертає вигадані дані. Інтегратор, що повірить контракту, отримає хибну ідентичність (наприклад, чужий `Id`), тож це дефект безпеки на рівні контракту.

## Impact Analysis (сім рівнів)

| Рівень | Вплив | Конкретні артефакти |
|--------|-------|---------------------|
| 1. Вимоги | Сценарій «відновити сесію за токеном» стає можливим. Інші сценарії (логін, реєстрація, турніри) не змінюються | SDD §4 рядок `GET /api/v1/users/me`; README сценаріїв не зачіпає |
| 2. Архітектура | Контролер `AuthController` отримує залежність `IUserRepository` (через `[FromServices]`, як `IParticipantRoster` у ЛР-10). Новий ADR не потрібен: шар і напрям залежностей не змінюються | SDD §3 (компоненти) — без змін |
| 3. Код | Радіус ураження — 1 продакшн-файл + 1 тестовий | `server/TournamentPlatformSystemWebApi.API/Controllers/AuthController.cs` (метод `Me`), `server/Tests/UsersMeEndpointTests.cs` (новий) |
| 4. API | Формат `UserDto` той самий → **additive** для контракту: значення стають правдивими, з'являється `404` (користувача з токена видалено) і `401` (токен без `sub`). Ендпоінт додається в `openapi.yaml` (1.1.1 → **1.2.0**, minor) | `docs/api/openapi.yaml`: операція `getCurrentUser`, схема `User` |
| 5. Дані | Лише читання (`GetUserWithDetails`), **міграцій немає** | — |
| 6. Тести | Нові: 3 юніт-тести контролера (профіль із токена, 401 без `sub`, 404 для відсутнього). Регресійний набір: `dotnet test server/Tests` (усі 48 + нові), контрактний тест `scripts/docs/contract_test.sh`, Spectral | CI `ci.yml` (server test), `docs.yml` (Spectral) |
| 7. Документація та експлуатація | `openapi.yaml`, `CHANGELOG.md` (Fixed), SDD §4 — прибрати позначку «заглушка». Runbook-и й алерти не змінюються (немає нових залежностей); SLI `availability` охоплює маршрут автоматично | DoD з [CONTRIBUTING](../developer/contributing.md) |

## Ризик

| Фактор | Оцінка | Пояснення |
|--------|--------|-----------|
| Ймовірність збою | 2 (низька) | один метод, наявний метод репозиторію, покрито тестами |
| Наслідки | 3 (середні) | 5xx на `/users/me` не блокує основні сценарії: клієнт ендпоінт поки не викликає (`grep "users/me" client/src` знаходить лише `onboarding-status`, `onboarding-complete`, `preferences`) |

## План відкату

1. Ознака проблеми: алерт `TournamentApiHighErrorRate` або 5xx на маршруті `api/v1/users/me` на дашборді протягом 15 хв після релізу.
2. `helm rollback tournament <попередня ревізія>` (compose: `git checkout <попередній тег> && docker compose up -d --build app`). Міграцій немає → відкат без втрати даних, ≤ 5 хв.
3. `git revert <коміт RFC-001>` у `main`, запис у CHANGELOG, RFC → стан `Rejected after rollback` з посиланням на інцидент.
